# Application & Infrastructure Security Architecture

This document outlines the security controls, hardening measures, and threat mitigations implemented across the Campus Lost & Found Portal.

---

## 1. Security Architecture & Threat Mitigations

```
Threat Actor (Internet)
       │
       ▼ [Blocked direct access to Ports 5000 and 3306]
   ┌───────┐
   │ Caddy │ TLS 1.3 Termination, Security Headers (HSTS, CSP, X-Frame-Options)
   └───┬───┘
       │ [Reverse Proxy Port 8080]
       ▼
   ┌───────┐
   │ Nginx │ Drops Hidden Files, Blocks Buffer Overflows (client_max_body_size 10M)
   └───┬───┘
       │ [Internal Docker Network only: prod-internal-net]
       ▼
   ┌─────────┐
   │ Gunicorn│ Non-Root User (UID 10001), ProxyFix Header Sanitization
   └────┬────┘
        │ [Parameterized SQLAlchemy Queries]
        ▼
   ┌─────────┐
   │  MySQL  │ Isolated Network, Strong Auth, Volume Persistence
   └─────────┘
```

## 2. Authentication & Authorization

### 2.1 Remediation of the Admin Elevation Vulnerability
* **Vulnerability in Previous Architecture**: The legacy code assigned `is_admin = (email in ADMIN_EMAILS)` directly upon registration. Because user email addresses were not verified via confirmation links, any unauthorized user registering with `admin@campus.edu` immediately acquired full administrator privileges.
* **Hardened Control**:
  1. Standard registration (`POST /api/register`) **never** grants administrator status automatically.
  2. Administrator status must be granted either:
     * Interactively via host CLI command:
       ```bash
       docker compose -f docker-compose.prod.yml exec -it api flask create-admin
       ```
     * During initial provisioning via the `X-Admin-Bootstrap-Token` header, matching the privately configured `ADMIN_BOOTSTRAP_TOKEN` in `/opt/lostandfound/.env`.
  3. All administrative actions (e.g. `DELETE /api/admin/items/<id>`) require verified JWT authentication and check `g.current_user.is_admin == True`.

### 2.2 JWT Authentication
* Signed with `HS256` using the server-side `SECRET_KEY`.
* Configurable token expiration (default 24 hours).
* Expired or tampered tokens return HTTP 401 and are rejected before execution reaches view handlers.

### 2.3 Password Security
* Passwords hashed using Werkzeug's default `scrypt` / `pbkdf2:sha256` key derivation algorithms.
* Plaintext passwords are never stored, logged, or serialized into JSON responses.

## 3. Container & Network Hardening

### 3.1 Network Isolation
* The backend API (`port 5000`) and MySQL (`port 3306`) are connected via the private internal bridge network `prod-internal-net`.
* No host ports are opened for the database or API.
* Frontend Nginx binds strictly to `127.0.0.1:8080`. External traffic reaches the application only through the Caddy HTTPS reverse proxy.

### 3.2 Non-Root Execution
* The backend container creates a dedicated unprivileged user `appuser` (UID 10001) and drops root privileges before launching Gunicorn:
  ```dockerfile
  USER appuser
  ```
* Should a vulnerability exist in application code, an attacker cannot modify container operating system binaries or escape to host root.

## 4. Input Validation & Content Security

### 4.1 File Upload Protection
* **Format & Extension Verification**: Only `jpg`, `jpeg`, `png`, and `webp` are accepted.
* **Magic Byte Content Inspection**: The file stream header is analyzed for genuine image signatures (e.g. `\x89PNG\r\n\x1a\n` for PNG, `\xff\xd8\xff` for JPEG, `RIFF...WEBP` for WebP). Spoofed text, scripts, or executables disguised as image files are rejected with HTTP 400.
* **File Size Cap**: Uploads exceeding 5 MB are rejected immediately.
* **Path Traversal Defense**: All filenames generated by the storage adapter use randomized UUIDs (`uuid.uuid4().hex`), preventing directory traversal or overwriting existing files.

### 4.2 Cross-Site Scripting (XSS) Prevention
* The frontend utilizes contextual HTML entity escaping (`escapeHtml()`) across all dynamic fields (`title`, `description`, `location`, `item_type`, `status`).
* Image URLs are sanitized with `sanitizeImageUrl()` to reject dangerous URI schemes (e.g. `javascript:`, `data:` scripts).
* Nginx and Caddy inject security headers:
  * `Content-Security-Policy`: Restricts script and object sources.
  * `X-Frame-Options: DENY`: Prevents clickjacking attacks.
  * `X-Content-Type-Options: nosniff`: Prevents MIME-confusion attacks.

---

## 5. Secret Management & Compliance
* **Zero Secrets in Code**: No API keys, passwords, or tokens exist in source code or Docker images.
* **Fail-Fast Production Startup**: If `SECRET_KEY` is missing or uses development default values in production (`ENV=production`), the application halts startup immediately with an explicit error.
* **Workload Identity Federation**: GitHub Actions CI/CD connects to Google Cloud without storing long-lived service account keys, using short-lived OIDC token exchanges.
